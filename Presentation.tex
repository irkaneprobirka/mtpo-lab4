\begin{frame}{Проблема}
Для одного приложения можно использовать разные средства тестирования.
\vspace{4mm}
\textbf{Задача:} сравнить Jest, Vitest и Mocha и выбрать подходящий инструмент.
\begin{itemize}
\item Все выполняют одинаковые 99 тестов.
\item Сравниваются время выполнения, работа процессора и память.
\item Результаты учитываются только при успешном прохождении всех тестов.
\end{itemize}
\end{frame}

\begin{frame}[fragile]{Что делает приложение}
Программа находит самый длинный палиндром, его длину и число палиндромных вхождений.
\begin{Verbatim}[fontsize=\small]
npm run start -- "abba"
npm run start -- --file data/example.json
\end{Verbatim}
Входной файл содержит строки в формате JSON:
\begin{Verbatim}[fontsize=\small]
{"strings": ["abba", "топот", ""]}
\end{Verbatim}
\textbf{Пример:} для abba ответ --- abba, длина 4, вхождений 6.
\end{frame}

\begin{frame}{Алгоритм Манакера}
Палиндром читается одинаково слева направо и справа налево.
\begin{enumerate}
\item Между символами добавляются разделители, чтобы одинаково обрабатывать чётные и нечётные палиндромы.
\item Для каждой позиции определяется, насколько далеко палиндром продолжается в обе стороны.
\item Уже найденная симметрия помогает избежать повторных сравнений.
\end{enumerate}
\textbf{Пример abba:} четыре отдельных символа, bb и abba. Всего 6 вхождений.
\vspace{3mm}
\par Время и дополнительная память растут линейно с длиной строки: $O(n)$.
\end{frame}

\begin{frame}{Для чего нужны Jest, Vitest и Mocha}
Все три инструмента запускают тесты и показывают найденные ошибки.
\vspace{4mm}
\par\textbf{Jest}\par
Готовый набор средств для проверки функций, серверного кода и компонентов интерфейса JavaScript-приложений.
\vspace{4mm}
\par\textbf{Vitest}\par
Подходит для JavaScript и TypeScript. Удобен в проектах с Vite, потому что может использовать настройки сборки приложения. Работает и с Node.js.
\vspace{4mm}
\par\textbf{Mocha}\par
Запускает тесты JavaScript-программ. Средства сравнения правильных и полученных ответов выбираются отдельно.
\end{frame}

\begin{frame}{Что проверяют тесты}
\begin{itemize}
\item Правильный ответ для обычных строк, пустой строки и повторяющихся символов.
\item Работу с русскими буквами, пробелами и эмодзи.
\item Чтение JSON и понятные сообщения при неверных данных.
\item Запуск программы через консоль и правильный вывод результата.
\item Работу на длинных строках.
\end{itemize}
\vspace{3mm}
\textbf{В каждом фреймворке --- одни и те же 99 тестов.}\par
Для 511 коротких строк ответ также сравнивается с независимым простым перебором.\par
Запуск всех тестов: \texttt{npm run test}.
\end{frame}

\begin{frame}[fragile]{Главные проверки: ответ и ошибка во входе}
\begin{Verbatim}[fontsize=\small]
test('Чётная длина', () => {
  assert.deepEqual(manacher('abba'), {
    longest: 'abba', length: 4, count: 6,
  });
});

test('Число внутри пакета', () => {
  assert.throws(
    () => parseInput('{"strings":[1]}'), /Элемент 1/
  );
});
\end{Verbatim}
\texttt{deepEqual} сравнивает весь ответ с правильным.\par
\texttt{throws} проверяет, что неверные данные вызывают ожидаемую ошибку.
\end{frame}

\begin{frame}[fragile]{Проверка программы через консоль}
\begin{Verbatim}[fontsize=\small]
test('Консоль обрабатывает строку', () => {
  const result = run(['abba']);
  assert.equal(result.status, 0);
  assert.match(result.stdout,
    /Самый длинный палиндром: "abba"/);
  assert.match(result.stdout, /вхождений: 6/);
  assert.equal(result.stderr, '');
});
\end{Verbatim}
\begin{itemize}
\item \texttt{run} запускает настоящую консольную программу.
\item Код 0 означает успешное завершение.
\item Тест проверяет ответ и отсутствие сообщений об ошибке.
\end{itemize}
\end{frame}

\begin{frame}{Как проверялось качество тестов}
Во временные копии приложения специально внесены три ошибки:
\begin{enumerate}
\item Выбор правого палиндрома вместо левого при равной длине.
\item Неправильное количество палиндромных вхождений.
\item Удаление пробелов из входных строк.
\end{enumerate}
\vspace{3mm}
\textbf{Все три фреймворка обнаружили каждую ошибку.}\par
Это подтверждает, что соответствующие тесты замечают неправильное поведение программы.
\end{frame}

\begin{frame}{Как проводилось сравнение}
\begin{itemize}
\item На одном компьютере по очереди запускались все 99 тестов.
\item Использовались строки длиной 100, 1000 и 10000 символов.
\item Для каждого размера и фреймворка выполнено 7 измерений.
\item Всего получено 63 успешных запуска. Первые пробные запуски не учитывались.
\item Отдельная программа измеряла время, работу процессора и память всех обнаруженных процессов тестового запуска.
\end{itemize}
\vspace{3mm}
Команды: \texttt{npm run benchmark} и \texttt{npm run results}.\par
В таблицах и на графике показана медиана: среднее по позиции значение среди семи результатов, упорядоченных по величине.
\end{frame}
