\chapter{Методы исследования} \label{ch1}

\section{Математическая постановка проблемы} \label{ch1:math}

Пусть задано множество фреймворков модульного тестирования
\[
    F=\{\text{Jest},\text{Vitest},\text{Mocha}\}.
\]
Каждый фреймворк запускает один и тот же набор тестов $T(D)$, где $D$ --- набор входных строк для алгоритма Манакера. Для каждого запуска фиксируются три метрики:
\[
    \tau_f(D) \text{ --- время выполнения, мс;}
\]
\[
    m_f(D) \text{ --- пиковое потребление оперативной памяти, МБ;}
\]
\[
    c_f(D) \text{ --- пиковая загрузка CPU, \%.}
\]
Для уменьшения влияния случайных колебаний каждый фреймворк запускается $R=5$ раз. Для метрики $x$ вычисляются среднее значение, стандартное отклонение и медиана:
\[
    \overline{x}_f=\frac{1}{R}\sum_{r=1}^{R}x_{f,r},
\]
\[
    \sigma_f=\sqrt{\frac{1}{R-1}\sum_{r=1}^{R}(x_{f,r}-\overline{x}_f)^2}.
\]
Для сводного сравнения используется нормированный показатель:
\[
    Score(f)=\frac{1}{3}\left(
    \frac{\overline{\tau}_f}{\max_{g\in F}\overline{\tau}_g}+
    \frac{\overline{m}_f}{\max_{g\in F}\overline{m}_g}+
    \frac{\overline{c}_f}{\max_{g\in F}\overline{c}_g}
    \right).
\]
Чем меньше значение $Score(f)$, тем экономичнее фреймворк по совокупности трех метрик.

\section{Алгоритм Манакера} \label{ch1:manacher}

Алгоритм Манакера предназначен для поиска палиндромов в строке за линейное время. В отличие от наивного расширения от каждого центра, которое в худшем случае требует $O(n^2)$ сравнений, алгоритм Манакера повторно использует информацию о ранее найденных палиндромах.

Сначала исходная строка преобразуется: между символами вставляется разделитель \texttt{\#}, а по краям добавляются сторожевые символы. Например:
\[
    abba \rightarrow \verb|^#a#b#b#a#$|.
\]
Затем для каждой позиции вычисляется радиус палиндрома. Поддерживаются текущий центр $center$ и правая граница $right$ самого правого найденного палиндрома. Если новая позиция лежит внутри этой границы, начальный радиус берется из зеркальной позиции.

\section{Псевдокод алгоритма измерения} \label{ch1:algorithm}

\begin{algorithm}[h]
\caption{Сравнение Jest, Vitest и Mocha на тестах алгоритма Манакера}
\label{alg:benchmark}
\KwInput{Файл данных $D$, множество фреймворков $F$, число повторов $R$}
\KwOutput{Таблица результатов $M$}
Загрузить строки из JSON или CSV\;
Проверить эталонные строки алгоритмом Манакера\;
$M \leftarrow \varnothing$\;
\ForEach{$f \in F$}{
    \For{$r \leftarrow 1$ \KwTo $R$}{
        Запустить тесты фреймворка $f$ как дочерний процесс\;
        $t_0 \leftarrow$ текущее время\;
        \While{процесс выполняется}{
            считать RSS-память процесса по PID\;
            считать загрузку CPU процесса по PID\;
            обновить пиковые значения памяти и CPU\;
        }
        $t_1 \leftarrow$ текущее время\;
        сохранить $(f,r,t_1-t_0,RSS_{max},CPU_{max})$ в $M$\;
    }
}
Сохранить $M$ в JSON и CSV\;
\end{algorithm}

\section{Иллюстративный пример} \label{ch1:example}

Рассмотрим строку \texttt{abacaba}. После преобразования:
\[
    \verb|^#a#b#a#c#a#b#a#$|.
\]
Центральный символ \texttt{c} становится центром максимального палиндрома. Радиус в преобразованной строке соответствует всей исходной строке, поэтому самый длинный палиндром равен \texttt{abacaba}. Количество палиндромных подстрок для этой строки равно 12.

В эталонном файле также используются строки \texttt{abba} и \texttt{abcdef}. Для \texttt{abba} самый длинный палиндром равен всей строке, для \texttt{abcdef} любой одиночный символ является палиндромом длины 1.

\section{Пошаговое выполнение на строке \texttt{abba}} \label{ch1:steps}

\begin{enumerate}
    \item Входная строка: \texttt{abba}.
    \item Преобразованная строка: \texttt{\^{}\#a\#b\#b\#a\#\$}.
    \item Алгоритм проходит позиции слева направо.
    \item На позиции разделителя между двумя \texttt{b} радиус расширяется до палиндрома \texttt{abba}.
    \item Максимальный радиус дает начало подстроки в исходной строке.
    \item Результат: самый длинный палиндром \texttt{abba}, число палиндромных подстрок равно 6.
\end{enumerate}
