\chapter{Направления развития} \label{ch6}

Предложенное приложение можно расширить несколькими способами. Во-первых, можно добавить больше тестовых файлов, чтобы сравнивать не только стоимость старта раннера, но и масштабирование при росте числа тестов. Во-вторых, можно включить режим покрытия кода, так как coverage часто используется в CI и может существенно менять потребление ресурсов. В-третьих, можно добавить сравнение с наивным алгоритмом расширения от центра, чтобы показать не только работу фреймворков, но и разницу алгоритмических сложностей $O(n)$ и $O(n^2)$.

Также полезно запускать эксперимент в CI, например в GitHub Actions для Node.js-проекта~\cite{github-actions-node}. Это позволит получать результаты в одинаковом окружении и отслеживать, как обновления Jest, Vitest, Mocha и Node.js меняют метрики.

Отдельное направление развития --- более точное измерение дерева процессов. В текущей версии метрики собираются по основному PID тестового раннера. Для фреймворков, создающих дочерние worker-процессы, можно дополнительно суммировать память и CPU по всему дереву процессов.
