\section{Расширение набора тестов} \label{ch6:tests}

В текущей версии используется один общий тестовый сценарий для всех фреймворков. Для более полной оценки можно добавить несколько типов тестов:
\begin{enumerate}
    \item большое число коротких тестов;
    \item небольшое число вычислительно тяжелых тестов;
    \item тесты с mock-функциями;
    \item тесты с асинхронным кодом;
    \item тесты с включенным покрытием кода.
\end{enumerate}

Такое расширение позволит отделить стоимость старта раннера от стоимости выполнения большого набора тестов.

\section{Улучшение мониторинга ресурсов} \label{ch6:monitoring}

В учебном проекте используется библиотека \texttt{pidusage}, которая обеспечивает переносимое измерение CPU и памяти по PID. Для промышленного исследования можно добавить платформенные источники данных: \texttt{Get-Process} в PowerShell на Windows, \texttt{ps} или \texttt{/proc} в Linux, а также сбор статистики по дереву процессов.

Это особенно важно для фреймворков, которые создают дочерние worker-процессы. В текущей работе измеряется основной процесс раннера, поэтому пиковые значения следует рассматривать как практическую оценку, а не как полный системный аудит.

\section{Автоматизация в CI} \label{ch6:ci}

Следующим шагом может быть запуск эксперимента в CI, например в GitHub Actions для Node.js-проекта~\cite{github-actions-node}. Тогда результаты будут сниматься в одинаковом окружении после каждого изменения зависимостей. Это позволит отслеживать, как обновления Jest, Vitest или Mocha влияют на скорость и ресурсы.

\section{Вывод по развитию} \label{ch6:summary}

Предложенный проект можно использовать как минимальную основу для дальнейших экспериментов. Его главное преимущество --- одинаковая прикладная функция и одинаковые входные данные для всех трех фреймворков. Это снижает риск некорректного сравнения и позволяет постепенно усложнять эксперимент.
