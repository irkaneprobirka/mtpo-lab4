\chapter*{Введение}
\addcontentsline{toc}{chapter}{Введение}

Автоматизированное модульное тестирование является одним из самых быстрых способов получать обратную связь о качестве JavaScript-кода. Однако выбор тестового фреймворка влияет не только на удобство написания тестов, но и на стоимость их регулярного запуска: время выполнения, потребление оперативной памяти и пиковую загрузку процессора. Эти параметры особенно важны при локальной разработке, в учебной демонстрации и в системе непрерывной интеграции, где тесты запускаются часто.

В работе рассматриваются три фреймворка модульного тестирования JavaScript: Jest, Vitest и Mocha. Jest является распространенным фреймворком с собственным раннером, средствами утверждений, mock-функциями и развитой документацией~\cite{jest-docs}. Vitest ориентирован на современную Vite/ESM-экосистему и предоставляет API, близкий к Jest~\cite{vitest-guide}. Mocha представляет более минималистичный раннер, который можно комбинировать с разными библиотеками утверждений или стандартным модулем \texttt{assert}~\cite{mocha-docs,node-assert}.

Цель работы --- провести сравнительный анализ Jest, Vitest и Mocha по трем ресурсным метрикам: скорости выполнения, пиковому потреблению оперативной памяти и пиковой загрузке CPU.

Для достижения цели были решены следующие задачи:
\begin{enumerate}
    \item сформулировать математическую постановку задачи сравнения тестовых фреймворков;
    \item разработать компактное программное средство на Node.js для запуска одинаковых модульных тестов в Jest, Vitest и Mocha;
    \item реализовать импорт входных данных из JSON и CSV;
    \item подготовить эталонный входной файл и эталонный выход для быстрой проверки корректности;
    \item подготовить авторский иллюстративный пример для демонстрации и отладки;
    \item измерить время выполнения, пиковую память и пиковый CPU каждого фреймворка;
    \item оформить псевдокод алгоритма измерения в окружении \texttt{algorithm};
    \item выполнить пошаговое выполнение метода на иллюстративных данных;
    \item описать установку и запуск программы.
\end{enumerate}

Изложение построено по принципу IMRAD. Во введении определяется проблема и цель. В разделе методов описываются постановка задачи, тестовые данные, алгоритм измерения и разработанное программное обеспечение. В разделе результатов приводятся полученные измерения. В обсуждении интерпретируются различия между фреймворками и ограничения эксперимента. В заключении формулируются итоговые выводы.
