Для иллюстрации в отчете используются ожидаемые результаты малого запуска. Конкретные значения времени и ресурсов зависят от версии Node.js, операционной системы, текущей нагрузки и режима энергопотребления. Поэтому в программном обеспечении сохраняются сырые результаты каждого запуска, а в отчете анализируется порядок величин и относительные различия.

\section{Входные данные переменной величины} \label{ch2:input}

Входной JSON-файл имеет следующую схему:
\begin{lstlisting}[breaklines=true]
{
  "name": "dataset-name",
  "size": 1000,
  "values": [1, 2, 3]
}
\end{lstlisting}

Поле \texttt{name} используется в отчете. Поле \texttt{size} задает итоговую длину массива. Поле \texttt{values} содержит начальные значения. Если длина массива меньше \texttt{size}, программа добавляет детерминированную последовательность. Это позволяет задавать входы переменной величины, не увеличивая размер репозитория.

Эталонный входной файл \texttt{reference\_input.json} содержит малый пример, для которого заранее подготовлен \texttt{reference\_output.json}. Такой пример нужен для быстрой проверки корректности программы перед запуском более дорогих измерений.

\section{Проверка корректности на эталонном файле} \label{ch2:reference}

Эталонный входной файл содержит массив \texttt{[9, 1, 5, 3, 7]}. Для него заранее известны:
\[
    sorted=[1,3,5,7,9],\quad sum=25,\quad mean=5,\quad min=1,\quad max=9.
\]
Эталонный выход сохранен в JSON-файле:
\begin{lstlisting}[breaklines=true]
{
  "sorted": [1, 3, 5, 7, 9],
  "sum": 25,
  "mean": 5,
  "min": 1,
  "max": 9
}
\end{lstlisting}

Перед сравнением фреймворков программа может выполнить быструю команду проверки: загрузить \texttt{reference\_input.json}, вычислить результат и сравнить его с \texttt{reference\_output.json}. Если проверка не прошла, запуск бенчмарка не имеет смысла: сначала нужно исправить функциональную ошибку.

\section{Инструкция по установке и запуску} \label{ch2:run}

Установка выполняется из каталога \texttt{benchmark\_app}:
\begin{lstlisting}[breaklines=true]
npm install
\end{lstlisting}

Быстрая проверка эталонного файла:
\begin{lstlisting}[breaklines=true]
npm run verify
\end{lstlisting}

Запуск полного сравнения:
\begin{lstlisting}[breaklines=true]
npm run benchmark -- --input data/author_example.json --runs 3
\end{lstlisting}

Отдельные команды для ручного запуска фреймворков:
\begin{lstlisting}[breaklines=true]
npm run test:jest
npm run test:vitest
npm run test:mocha
\end{lstlisting}

Результаты сохраняются в каталог \texttt{reports}. JSON-отчет удобен для последующей автоматической обработки, CSV-файл --- для импорта в электронные таблицы и построения графиков.

\section{Компактность и комментирование кода} \label{ch2:code-quality}

Код проекта намеренно ограничен одним основным файлом \texttt{src/benchmark.js}. В нем выделены функции чтения входа, вычисления эталона, проверки результата и запуска дочернего процесса. Комментарии оставлены в местах, где важно объяснить измерение ресурсов и детерминированное дополнение массива. Такая структура делает проект удобным для code review: проверяющий видит весь эксперимент без перехода по большому числу файлов.
