\chapter{Расширенная методика тестирования} \label{ch5}

\section{Функциональная проверка} \label{ch5:functional}

Функциональная проверка отвечает на вопрос: правильно ли программа вычисляет результат независимо от выбранного фреймворка. Она выполняется на эталонном входе и сравнивается с заранее подготовленным эталонным выходом. Для массива \texttt{[9,1,5,3,7]} результат известен заранее, поэтому ошибка обнаруживается без анализа производительности.

Этот этап соответствует классическому модульному тестированию: тестируется небольшая функция с детерминированным результатом. Jest, Vitest и Mocha получают одинаковую проверку, различается только синтаксис assertions.

\section{Нагрузочная проверка} \label{ch5:load}

Нагрузочная проверка отвечает на другой вопрос: сколько ресурсов требуется фреймворку для запуска тестов. Она выполняется после функциональной проверки и включает несколько повторов. Повторы нужны, потому что первый запуск может быть дороже из-за загрузки модулей, прогрева JIT и состояния файлового кеша.

Для каждого повтора фиксируются:
\begin{enumerate}
    \item номер запуска;
    \item имя фреймворка;
    \item размер входного массива;
    \item код завершения процесса;
    \item время выполнения в миллисекундах;
    \item пиковый RSS в мегабайтах;
    \item пиковая оценка CPU в процентах.
\end{enumerate}

\section{Подготовка к code review} \label{ch5:review}

Требование быстрого разворачивания в процессе code review выполнено за счет следующих решений:
\begin{enumerate}
    \item отсутствуют внешние сервисы и базы данных;
    \item все зависимости устанавливаются одной командой \texttt{npm install};
    \item эталонная проверка выполняется без запуска тяжелого бенчмарка;
    \item входные файлы лежат в репозитории;
    \item структура проекта помещается на одну страницу отчета.
\end{enumerate}

Проверяющий может сначала открыть \texttt{requirements.txt}, затем выполнить \texttt{npm install} и \texttt{npm run verify}. Если этот шаг прошел, можно запускать полный бенчмарк. Такой порядок экономит время и упрощает поиск ошибок.

\section{Расширение эксперимента} \label{ch5:extension}

Предложенную программу можно расширить без изменения отчета. Возможные направления:
\begin{enumerate}
    \item добавить больше тестовых файлов, чтобы измерять не только старт раннера, но и масштабирование по числу тестов;
    \item включить режим покрытия кода и сравнить стоимость coverage;
    \item добавить отдельные входы для малых, средних и больших массивов;
    \item выполнять медиану по пяти или десяти запускам;
    \item запускать эксперимент в CI, например в GitHub Actions для Node.js-проектов~\cite{github-actions-node}.
\end{enumerate}

Эти улучшения не меняют базовую математическую постановку: для каждого фреймворка по-прежнему измеряется вектор метрик $(\tau, m, c)$.
